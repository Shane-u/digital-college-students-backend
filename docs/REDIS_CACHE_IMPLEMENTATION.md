## 二、缓存策略说明

### 缓存 Key 命名规范
- 格式：`{模块}:{类型}:{标识}`
- 示例：
  - `post:detail:123:456` - 帖子详情（帖子ID:用户ID）
  - `contest:list:current:1:size:10:...` - 竞赛列表
  - `user:123` - 用户信息

### 缓存过期时间
- 帖子列表：5 分钟
- 帖子详情：10 分钟（登录用户）/ 5 分钟（匿名用户）
- 竞赛列表：10 分钟
- 竞赛详情：30 分钟（外部 API）
- 用户信息：1 小时
- 题目列表：1 小时
- 推荐结果：24 小时
- 用户画像：7 天

### 缓存清除策略
- **主动清除**：数据更新、删除时清除相关缓存
- **过期清除**：依赖 Redis 的过期机制
- **批量清除**：使用通配符模式批量删除（如 `post:*`）

## 未来加入消息队列计划！

1. **用户画像更新**（推荐服务）
   - 原因：频繁触发，需要可靠执行
   - 推荐：使用 RabbitMQ 或 RocketMQ

2. **爬虫任务**
   - 原因：耗时操作，需要异步处理
   - 推荐：使用消息队列解耦

3. **邮件/短信发送**
   - 原因：外部服务调用，需要重试机制
   - 推荐：使用消息队列保证可靠性

### 消息队列选型

#### RocketMQ
- **优点**：
  - 阿里开源，适合国内环境
  - 性能优秀，支持高并发
- **适用场景**：大规模爬虫任务、高并发场景
